Harbor Python 批量上传 ACR 操作说明

适用于把 source code/harbor/python/ 下的 python-XXX 任务批量构建成 Docker 镜像并推送到阿里云 ACR。上传动作只在 ECS 上执行，本地 DSW 不执行 build/push。

本地数据目录
/mnt/data/zpy/sci-swe/source code/harbor/python/
ECS 目标目录
/root/sci-swe/harbor/python/
ACR 公网推送地址
agent-rl-acr-registry.cn-beijing.cr.aliyuncs.com
ACR VPC 拉取地址
agent-rl-acr-registry-vpc.cn-beijing.cr.aliyuncs.com
Namespace
sci-swe-python
批量上传脚本
build_push_all_harbor.sh
远端清理脚本
delete_stale_acr_tags.sh

0. 当前状态

你已经成功上传了 python-001 和 python-002。当前本地 harbor/python 下有 197 个 python-XXX 目录，缺少 python-003、python-076、python-090。批量脚本只扫描并上传实际存在的目录。

建议正式上传时使用 --skip 001,002，避免重复上传已经完成的两个镜像。

1. 在 DSW 上同步数据到 ECS

这一步只复制文件，不构建镜像。密码或认证方式按你的 ECS 配置执行。

rsync -avz --progress \
  --exclude 'build-logs/' \
  "/mnt/data/zpy/sci-swe/source code/harbor/python/" \
  root@47.236.251.245:/root/sci-swe/harbor/python/

2. 登录 ECS 并准备 ACR

下面所有 Docker 命令都在 ECS 上执行。

ssh root@47.236.251.245
cd /root/sci-swe/harbor/python
chmod +x build_push_all_harbor.sh

确认 namespace 存在并开启自动创建仓库：

aliyun cr CreateNamespace \
  --InstanceId cri-h0hcfm1j42x9wiw6 \
  --NamespaceName sci-swe-python \
  --region cn-beijing || true

aliyun cr UpdateNamespace \
  --InstanceId cri-h0hcfm1j42x9wiw6 \
  --NamespaceName sci-swe-python \
  --AutoCreateRepo true \
  --DefaultRepoType PUBLIC \
  --region cn-beijing

登录 ACR。可以使用你已有的 docker login 方式，或按原 ACR 指南获取 token 后登录：

docker login agent-rl-acr-registry.cn-beijing.cr.aliyuncs.com
如果没有登录或 namespace 未开启 AutoCreateRepo，docker push 通常会报 denied。

3. 先做 dry-run

dry-run 只打印计划执行的 Docker 命令，不会构建、不会推送。

bash /root/sci-swe/harbor/python/build_push_all_harbor.sh \
  --tasks-dir /root/sci-swe/harbor/python \
  --skip 001,002 \
  --jobs 4 \
  --dry-run

如果只想测试少数任务：

bash /root/sci-swe/harbor/python/build_push_all_harbor.sh \
  --tasks-dir /root/sci-swe/harbor/python \
  --only 004,045,200 \
  --dry-run

4. 正式批量构建并推送

推荐用 tmux，避免 SSH 断开导致任务中断。你这台 ECS 是 16 vCPU、61Gi 内存，建议先用 --jobs 4；如果稳定再试 --jobs 6，不建议直接开到 8 路以上。

tmux new -s harbor-python-upload

bash /root/sci-swe/harbor/python/build_push_all_harbor.sh \
  --tasks-dir /root/sci-swe/harbor/python \
  --skip 001,002 \
  --jobs 4

断开 tmux：按 Ctrl+B，再按 D。重新连接：

tmux attach -t harbor-python-upload
脚本会把每个镜像推送到：
agent-rl-acr-registry.cn-beijing.cr.aliyuncs.com/sci-swe-python/python-XXX:latest
并行模式下每个任务仍然有独立日志，最终汇总在 build-logs/success.txt、failed.txt 和 skipped.txt。

5. 查看日志和失败任务

总日志和结果清单都在 /root/sci-swe/harbor/python/build-logs/。

tail -f /root/sci-swe/harbor/python/build-logs/summary.log

cat /root/sci-swe/harbor/python/build-logs/success.txt
cat /root/sci-swe/harbor/python/build-logs/failed.txt
cat /root/sci-swe/harbor/python/build-logs/skipped.txt

每个任务还有单独日志，例如：

tail -80 /root/sci-swe/harbor/python/build-logs/python-045.log

6. 重试失败任务

如果只有少数任务失败，用 --only 重试，不需要重跑全部。

bash /root/sci-swe/harbor/python/build_push_all_harbor.sh \
  --tasks-dir /root/sci-swe/harbor/python \
  --only 045,068,200

如果怀疑 Docker 缓存导致问题：

bash /root/sci-swe/harbor/python/build_push_all_harbor.sh \
  --tasks-dir /root/sci-swe/harbor/python \
  --only 045 \
  --no-cache

7. 验证 ACR 镜像

列出 namespace 下的仓库：

aliyun cr ListRepository \
  --InstanceId cri-h0hcfm1j42x9wiw6 \
  --RepoNamespace sci-swe-python \
  --PageSize 100 \
  --region cn-beijing

拉取并验证一个镜像：

docker pull agent-rl-acr-registry.cn-beijing.cr.aliyuncs.com/sci-swe-python/python-004:latest

docker run --rm \
  agent-rl-acr-registry.cn-beijing.cr.aliyuncs.com/sci-swe-python/python-004:latest \
  /bin/bash -lc 'PYTHONPATH=/app/workspace bash /tests/test.sh'
ACS 沙箱里应使用 VPC 地址：
agent-rl-acr-registry-vpc.cn-beijing.cr.aliyuncs.com/sci-swe-python/python-XXX:latest

8. 清理 ECS 磁盘

脚本默认每个任务推送后会清理本地镜像。必要时可以额外清理 Docker 缓存：

docker image prune -a -f
docker builder prune -f
df -h /
不要在上传任务运行中执行全量 prune，避免影响正在构建的镜像。

9. 删除 ACR 上已经不用的旧镜像

如果本地 python-XXX 目录减少了，ACR 里之前推上去的 python-XXX:latest 不会自动消失。需要在 ECS 上用清理脚本删除远端 tag。

当前场景：之前上传了 197 个镜像，现在本地 harbor-program/python 只有 161 个任务。旧版本原本就缺少 003、076、090，所以真正需要清理的是 197 - 161 = 36 个远端 latest tag。

先同步新版 harbor-program/python 到 ECS，例如：

rsync -avz --progress \
  --exclude 'build-logs/' \
  "/mnt/data/zpy/sci-swe/source code/harbor-program/python/" \
  root@47.236.251.245:/root/sci-swe/harbor-program/python/

登录 ECS 后先 dry-run。dry-run 只打印将要执行的 aliyun cr DeleteRepoTag 命令，不会真的删除。

ssh root@47.236.251.245
cd /root/sci-swe/harbor-program/python
chmod +x delete_stale_acr_tags.sh

bash delete_stale_acr_tags.sh

你应该看到类似下面的汇总，重点确认 region=cn-beijing、namespace=sci-swe-python、delete_candidates=36：

ACR stale tag cleanup
tasks_dir=/root/sci-swe/harbor-program/python
region=cn-beijing
instance_id=cri-h0hcfm1j42x9wiw6
namespace=sci-swe-python
tag=latest
delete_candidates=36

[DRY-RUN] aliyun cr GetRepository ... --RepoName python-002 --region cn-beijing
[DRY-RUN] aliyun cr DeleteRepoTag ... --RepoId  --Tag latest --region cn-beijing
[DRY-RUN] aliyun cr GetRepository ... --RepoName python-011 --region cn-beijing
[DRY-RUN] aliyun cr DeleteRepoTag ... --RepoId  --Tag latest --region cn-beijing
...

确认 dry-run 列表只包含你已经删除的编号后，再真正删除：

bash delete_stale_acr_tags.sh --apply
这个脚本删除的是 ACR 远端的 latest 镜像版本，不是本地 Docker 镜像。默认不会删除 ACR 仓库本身。

如果 ECS 上实际路径不是 /root/sci-swe/harbor-program/python，用 --tasks-dir 指定本地任务目录。脚本会按这个目录判断哪些编号应该保留。

bash delete_stale_acr_tags.sh \
  --tasks-dir /root/sci-swe/harbor/python \
  --apply

如果只想删除指定编号：

bash delete_stale_acr_tags.sh --only 002,011,018 --apply

删除后可以用阿里云 CLI 查看仓库或 tag。下面命令用于先查某个仓库的 RepoId，然后检查 tag 是否还存在：

aliyun cr GetRepository \
  --InstanceId cri-h0hcfm1j42x9wiw6 \
  --RepoNamespaceName sci-swe-python \
  --RepoName python-002 \
  --region cn-beijing

# 用上一步返回的 RepoId 查询 tag
aliyun cr ListRepoTag \
  --InstanceId cri-h0hcfm1j42x9wiw6 \
  --RepoId  \
  --region cn-beijing

如果 python-002:latest 已删除，后续 ACS 就不能再拉这个旧镜像。保留下来的任务，例如 python-001、python-004，不会受影响。
